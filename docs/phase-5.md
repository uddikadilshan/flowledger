# Phase 5 notification centre

In-app alerts are generated by the private database generator via authenticated refresh or the administrator-only notification cycle. Per-user/per-business inboxes and preferences are RLS protected. A daily key prevents repeat alerts for the same obligation and day. Alert values are snapshots, not live balances. Collection requirement cleared means funds cover remaining month-end obligations after a target alert; it is not a historical fixed daily target achievement. Preferences affect future generation, not existing alerts. The app polls every minute while open. No financial mutations are made.

Production migration must be approved and applied before deploying the frontend. Optional cron setup in supabase/setup/notification-cron.sql requires pg_cron (available but not installed on the connected project). Schedule runs every 15 minutes, creating inbox records even while the app is closed. Inspect cron job run details and monitor workload before enabling. Disable via cron.unschedule('flowledger-notification-cycle').

Device notification test requests permission and uses the existing service worker showNotification. This is NOT remote web push. Remote push requires VAPID keys stored securely, per-user device subscription lifecycle, authenticated registration, endpoint validation, server delivery with retries and a service worker push handler. No delivery credentials have been configured, and no remote push service has been deployed. Do not describe the device test as closed-app delivery. Keep notifications generic on lock screens. iOS requires supported installed web app.
